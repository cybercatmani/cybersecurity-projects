# SOC Sentinel — Security Monitoring & Incident Response Lab

A beginner-friendly defensive home lab for collecting Windows endpoint telemetry, centralizing events in Wazuh, investigating alerts, and documenting incident response.

> Use only systems and networks you own or have explicit permission to monitor. This project uses harmless test activity; it contains no malware or exploit code.

## What you will build
- Windows 11 endpoint telemetry with **Sysmon**
- Centralized collection and alerting with **Wazuh**
- Optional network IDS telemetry with **Suricata EVE JSON**
- A custom Wazuh rule mapped to MITRE ATT&CK
- Alert triage and incident documentation
- A Python utility to summarize exported Wazuh JSON alerts

## Quick start
1. Read `docs/01-lab-design.md` and `docs/02-installation.md`.
2. Install Wazuh all-in-one on an Ubuntu Server VM using the official quickstart.
3. Install the Wazuh agent and Sysmon on Windows 11.
4. Configure the agent to collect `Microsoft-Windows-Sysmon/Operational`.
5. Merge `config/wazuh/local_rules.xml` into the manager's local rules file.
6. Run `scripts/windows/Invoke-SafeSimulation.ps1` and confirm rule `100100` alerts.
7. Export a small alert sample as JSON and run `python tools/summarize_alerts.py sample-data/sample-alerts.json`.
8. Complete the incident report template in `docs/incident-report-template.md`.

## Hardware and network
A practical starting point for a single endpoint is an Ubuntu Server VM with 4 vCPU, 8 GB RAM and 50 GB disk, plus your Windows host. Check current Wazuh requirements before allocating resources. Use a private/host-only lab network; do not expose the dashboard or management ports to the public internet.

## Important limitations
- This is a learning lab, not a production SOC deployment.
- Tool versions, package names and UI labels change; use current vendor documentation.
- Rule `100100` detects only the unique marker generated by this lab's safe simulation. It is not a general malicious-PowerShell detector.
- Suricata sees only traffic visible to its capture interface. A NAT/host-only VM may not see all physical-network traffic.
- Do not commit passwords, private keys, certificates, raw personal data or unredacted logs.
